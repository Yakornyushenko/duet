# Личное пространство и объединение

## Что меняется

- После входа пользователь может работать один: создавать даты, желания и заметки.
- Пока партнёр не подключён, доступны списки желаний «Вместе» и «Мои».
- Дата начала отношений необязательна. Без неё счётчик дней не отображается.
- При подключении по коду оба пространства объединяются. Сохраняются идентификаторы дат, желаний и заметок, фото, комментарии, история выполнения и корзина.
- Личные желания приглашённого переходят в его личный список; общие остаются в «Вместе».
- Категорий максимум 6. Перед соединением показаны категории обоих пользователей: одинаковые итоговые названия объединяются. Если разных названий больше 6, нужно выбрать объединение вручную. Никакие даты для соблюдения лимита не удаляются.
- Дата начала отношений берётся из пространства приглашающего; если там она не задана — из пространства присоединяющегося. Позже её можно изменить в профиле.
- Объединение не создаёт уведомление для каждого перенесённого желания. Последующие изменения уведомляют партнёра как прежде.

## Применение — вручную владельцем проекта

1. Сделать резервную копию рабочей базы перед изменением схемы.
2. Убедиться, что предыдущие миграции применены, включая `20261001020000_harden_client_permissions.sql`.
3. В SQL Editor Supabase выполнить **полностью** файл `supabase/migrations/20261001030000_personal_workspaces.sql` (от `begin` до `commit`). Это подготовленная, но не применённая агентом миграция.
4. Обновить приложение у обоих пользователей. Новому клиенту нужны функции из этой миграции.
5. Один пользователь создаёт код. Второй вводит его, проверяет итоговые категории и подтверждает объединение.

Не запускать миграцию повторно после успешного применения. Если уже применялась ранняя версия этого файла с переходом без переноса, требуется отдельная корректирующая миграция: не удаляйте таблицы и не пытайтесь повторять этот файл частями.

Миграция сама по себе не объединяет существующие пространства. Перенос выполняется только после подтверждения в приложении, в одной транзакции. При ошибке перенос целиком откатывается. Отмена успешного объединения через приложение не предусмотрена.

## Фотографии и безопасность

Файлы остаются в закрытом `wish-photos` по прежним путям. Старое пространство остаётся техническим указателем для доступа к ним, без активных участников. Не удаляйте такие строки из `couples` и не переносите файлы вручную.

Подготовка соединения ограничена пятью попытками за 15 минут. Подтверждение привязано к пользователю и действует 10 минут; изменение кода, участников или категорий требует повторной подготовки. Все сохранённые данные, включая корзину заметок, станут доступны обоим — это явно указано перед соединением.

## Проверки

`node tests/personal-workspaces.cjs` использует одноразовый локальный PostgreSQL (PGlite), не читает `.env` и не подключается к Supabase. Проверяются все миграции, лимит категорий, перенос, откат при ошибке фото, устаревшие категории, повторное подтверждение, права третьего пользователя и ограничение попыток. Для теста нужен отдельный runtime: `npm install --prefix .android-bootstrap/merge-test --no-save @electric-sql/pglite`.

Также выполнены проверка типов и существующие тесты приложения. Проверка на двух телефонах и реальной инфраструктуре Supabase остаётся после ручного применения миграции и обновления приложения. Локальный тест не проверяет доставку push, Storage API, Realtime по сети и конкурентные запросы отдельных соединений.
