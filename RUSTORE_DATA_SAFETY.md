# Декларация данных и разрешений для RuStore

Актуально для приложения «Дуэт» 1.0.0 на 14 октября 2026 года. Перед каждой новой версией сверять этот файл с кодом, подключёнными SDK и политикой конфиденциальности.

## Чувствительные разрешения

RuStore должен обнаружить три чувствительных разрешения. Вставить следующие обоснования в консоль.

| Разрешение | Обоснование |
| --- | --- |
| `POST_NOTIFICATIONS` | Используется только с разрешения пользователя для локальных напоминаний о важных датах и для уведомлений о новых желаниях и вопросе дня. Основные функции приложения доступны без разрешения на уведомления. |
| `READ_EXTERNAL_STORAGE` (`maxSdkVersion=32`) | На Android 12L и более ранних версиях используется при выборе пользователем фотографии из системной медиатеки для добавления к желанию. Приложение получает доступ только после действия пользователя; камера, микрофон, контакты и геолокация не запрашиваются. |
| `WRITE_EXTERNAL_STORAGE` (`maxSdkVersion=32`) | Декларируется библиотекой выбора и обработки изображения на Android 12L и более ранних версиях. Используется только в сценарии выбранной пользователем фотографии; постоянное фоновое сканирование хранилища не выполняется. |

`INTERNET` и `VIBRATE` относятся к безопасным разрешениям, но их назначение очевидно: синхронизация с сервером и вибрация уведомлений.

## Категории и типы данных

Отметить в консоли все перечисленные ниже типы, даже если RuStore не добавил их автоматически по манифесту.

| Категория RuStore | Тип данных | Для чего используется |
| --- | --- | --- |
| Личная информация | Имя | Имя профиля и отображение пользователя партнёру. |
| Личная информация | Адрес электронной почты | Регистрация, вход, подтверждение email, восстановление доступа и поддержка. |
| Личная информация | ID пользователей | Идентификатор аккаунта, связи пары и контроль доступа. |
| Личная информация | Другие данные | Дата начала отношений, часовой пояс, подтверждение совершеннолетия и настройки пары. |
| Фото и видео | Фотографии | Необязательные фотографии, выбранные пользователем для желаний. |
| Сообщения | Другие сообщения в приложениях | Комментарии к желаниям, доступные только участникам пары. |
| Действия в приложении | Другой пользовательский контент | Названия и описания дат и желаний, заметки, чек-листы и ответы на вопрос дня. |
| Действия в приложении | Другие действия | Настройки напоминаний и вопросов, отметки выполнения событий, параметры категорий. |
| Идентификаторы | ID устройства или другие идентификаторы | Expo push-токен/идентификатор установки, необходимый для доставки уведомлений. |
| Данные о работе приложения | Диагностика | IP-адрес, сведения об устройстве или браузере, время и результат запроса могут попадать в технические журналы инфраструктурных поставщиков. |

Не отмечать местоположение, контакты, календарь устройства, аудио, видео, финансовые данные, историю просмотра, историю поиска, список установленных приложений, рекламный идентификатор или аналитику поведения: текущая версия их не собирает.

## Передача поставщикам

- Supabase: авторизация, база данных, серверные функции и закрытое хранилище фотографий.
- Resend: служебные письма авторизации.
- Expo и Google Firebase Cloud Messaging: push-токены и доставка Android-уведомлений.
- Cloudflare: публичные веб-страницы «Дуэт».

В форме RuStore считать передачей третьей стороне также отправку данных через SDK и поставщикам инфраструктуры, даже если они обрабатывают данные только от имени разработчика.

## Заявления о безопасности

- Данные передаются по HTTPS.
- Удаление аккаунта доступно внутри приложения.
- Рекламы, рекламных SDK, платных функций и поведенческой аналитики нет.
- Доступ к общему содержимому ограничен двумя участниками пары.
- Камера, микрофон, контакты и геолокация не запрашиваются.

## Обязательная юридическая проверка до модерации

RuStore требует соблюдения российского законодательства о персональных данных, включая основания обработки, отдельное согласие в применимых случаях и локализацию первичного сбора данных граждан РФ. Текущая политика прямо описывает Supabase, Resend, Expo и Google, а также возможную трансграничную обработку. До публичного релиза нужно получить профильную юридическую оценку:

1. применимо ли уведомление Роскомнадзора об операторе персональных данных;
2. требуется ли отдельная форма согласия при регистрации вместо одной ссылки на политику;
3. соответствует ли текущая архитектура требованию локализации первичного сбора данных граждан РФ;
4. нужны ли отдельные правила пользовательского контента, жалоба и блокировка для закрытого пространства пары.

Этот файл — техническая инвентаризация, а не юридическое заключение.
