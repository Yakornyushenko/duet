# Дуэт

Мобильное приложение для пары: связывает двух пользователей по одноразовому коду и хранит общий календарь важных дат.

## Что уже работает

- регистрация и вход по email и паролю;
- создание пространства пары с датой начала отношений;
- код приглашения из 6 символов, действующий 24 часа;
- присоединение второго пользователя по коду;
- общий счётчик дней вместе;
- однократные и ежегодные даты;
- создание, редактирование и удаление дат;
- синхронизация изменений между партнёрами через Supabase Realtime;
- интерфейс «Тёплый закат» для Android и iOS.

Проект использует Expo SDK 54 намеренно: эту версию можно открыть в Expo Go на физическом iPhone прямо с Windows.

## Запуск приложения

Потребуются Node.js LTS и pnpm.

```bash
pnpm install
pnpm start
```

Установите Expo Go из App Store, затем отсканируйте QR-код обычной камерой iPhone. Компьютер и телефон должны находиться в одной Wi-Fi сети. Если соединение не устанавливается, запустите `pnpm start --tunnel`.

Для регистрации и работы с общими данными приложение должно быть подключено к Supabase через файл `.env`.

## Подключение Supabase

1. Создайте проект в Supabase.
2. Выполните SQL из `supabase/migrations/20260915000000_initial_schema.sql` в SQL Editor.
3. Скопируйте `.env.example` в `.env`.
4. Добавьте URL проекта и publishable key из окна Connect в Supabase.
5. Перезапустите Expo.

```env
EXPO_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
```

Publishable key можно использовать в клиентском приложении: доступ к данным защищён политиками Row Level Security из миграции. Service role key добавлять в приложение нельзя.

При включённом подтверждении email в Supabase потребуется настроить deep link для ссылки подтверждения. Для первого локального теста подтверждение email можно временно отключить в настройках провайдера Email.

## Push-уведомления о желаниях

После настройки доставки, когда один партнёр добавляет, меняет или комментирует желание, второй получает push. Автору изменения уведомление не приходит. Наличие кода само по себе не означает, что доставка уже подключена.

При изменении желания БД ставит задачу в очередь. Серверный планировщик раз в минуту вызывает защищённую Edge Function `process-wish-jobs`, которая отправляет push через Expo (Android — FCM, iOS — APNs). Приложению не нужно оставаться открытым. Ошибки сохраняются в `wish_jobs.last_error`, максимум 8 попыток. Принятие сообщения Expo не гарантирует доставку на телефон; проверка delivery receipts пока не реализована. При частичном сбое повторная попытка может дать дубликат.

Чтобы уведомления заработали после релиза, один раз нужно выполнить настройку. Все команды — из корня проекта, нужен аккаунт Expo (`npx eas login`).

### 1. Связать проект с Expo (появится projectId)

```bash
npx eas init
```

### 2. Android: Firebase Cloud Messaging (FCM)

1. Откройте [console.firebase.google.com](https://console.firebase.google.com) и создайте проект (или возьмите существующий).
2. Добавьте Android-приложение с package `app.duet.mobile`.
3. Скачайте `google-services.json` и положите его **в корень проекта** (рядом с `app.json`).
4. Создайте приватный JSON-ключ сервисного аккаунта Firebase для **FCM V1** и загрузите его в Expo. Это другой файл, не `google-services.json`. Не добавляйте приватный ключ в репозиторий и не отправляйте в чат:

```bash
npx eas credentials
```

Выберите Android → ваш профиль сборки → Google Service Account / FCM, и следуйте подсказкам.

### 3. iOS: APNs

Для iOS нужен аккаунт Apple Developer и настроенные APNs credentials / provisioning profile. Их можно настроить через `npx eas credentials` → iOS.

### 4. Задеплоить функцию отправки

1. Выполните ещё не применённые миграции, включая `20260921000000_wish_details.sql`. Не запускайте её повторно, если таблицы уже созданы.
2. В Supabase → Edge Functions → Secrets добавьте `WISH_WORKER_SECRET` — случайный секрет длиной не менее 32 символов. Он используется только на сервере.
3. Разверните функцию: `supabase functions deploy process-wish-jobs`. Конфигурация в `supabase/config.toml` отключает JWT-проверку шлюза: сама функция проверяет серверный секрет, запросы приложения отклоняются.
4. Включите расширения `pg_cron` и `pg_net`. В Vault создайте `wish_worker_url` с адресом функции и `wish_worker_secret` с тем же секретом.
5. Выполните `supabase/setup-wish-worker.sql` для запуска каждую минуту.

### 5. Собрать приложение

```bash
npx eas build --platform android
npx eas build --platform ios
```

Локальная Android-сборка тоже поддерживает push: нужны projectId Expo, нативная конфигурация Firebase и FCM V1 credentials на стороне Expo. После добавления `google-services.json` обновите нативный проект командой `pnpm exec expo prebuild --platform android` (без `--clean`), затем пересоберите APK. Приватный FCM-ключ в APK не включается.

### Проверить на двух телефонах

После применения `supabase/migrations/20260922000000_debounce_wish_notifications.sql`
правки одного желания от одного автора одному получателю объединяются до начала отправки.
Каждая правка откладывает готовность на 60 секунд; с минутным Cron отправка начинается
примерно через 1–2 минуты тишины. Создание сохраняет тип «Добавлено желание» с последним
названием. Создание и удаление до первой попытки отправки отменяют push о желании.
Комментарии идут отдельно. Уже взятые на отправку/ранее обработанные задачи не объединяются
с новыми правками. Старые задачи, созданные до миграции, остаются без объединения.
Проверки для тестовой БД: `supabase/tests/wish_notification_debounce.sql` (с откатом).

Войти под разными пользователями одной пары, разрешить уведомления через существующий раздел колокольчика. На первом устройстве добавить/изменить желание или оставить комментарий; на втором дождаться push и проверить открытие желания нажатием. Автор не должен получать свой push. Проверить также закрытое приложение и выход из аккаунта. Если push не приходит, проверить `wish_devices`, `wish_jobs.last_error`, журнал функции и запуск задания Cron. На главной новые элементы не добавляются.

Официальная настройка: [Expo / FCM V1](https://docs.expo.dev/push-notifications/fcm-credentials/), [Supabase / запуск по расписанию](https://supabase.com/docs/guides/functions/schedule-functions).

## Установка на подключённый Android-телефон

```bash
pnpm android:phone
```

Команда собирает release APK для `arm64-v8a` и устанавливает его на Samsung SM-S931B.

Production-сборки Android и iOS выполняются через EAS Build. Собственный Mac для облачной сборки и отправки в TestFlight не требуется.
