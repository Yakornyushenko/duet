# Вопрос дня — подготовка и запуск

Изменения подготовлены локально. Миграцию и серверную функцию агент не применял.

## Запуск владельцем проекта

1. Применить предыдущую миграцию личных пространств, если ещё не применена.
2. После резервного копирования выполнить целиком `supabase/migrations/20261001040000_daily_questions.sql` через SQL Editor Supabase. Повторно после успеха не запускать.
3. Обновить существующую функцию: `npx supabase functions deploy process-wish-jobs`. Секрет `WISH_WORKER_SECRET` остаётся прежним.
4. Проверить, что уже настроенный минутный Cron вызывает `process-wish-jobs`. Новый Cron создавать не нужно — иначе получится два обработчика одного расписания. Без работающего Cron вопросы будут доступны в приложении, но ежедневные push не отправятся.
5. Обновить приложение обоим партнёрам. В «Ещё → Вопрос дня» каждый нажимает «Начать». Ежедневные вопросы активны только при согласии обоих.
6. В разделе выбрать общее время и часовой пояс пары. По умолчанию 19:00 Europe/Minsk; кнопка позволяет применить часовой пояс устройства для обоих.
7. На каждом устройстве разрешить уведомления кнопкой раздела. Для удалённых push требуется установленная сборка с настроенными FCM/APNs, не Expo Go.

## Поведение

- Меню «Ещё» содержит новый раздел. На главную элементы не добавлялись.
- При первом открытии показывается объяснение. Принятие/отказ сохраняется на аккаунт, поэтому на другом устройстве попап повторно не нужен.
- Один вопрос на пару и календарный день общего часового пояса. Вопрос не меняется при повторном открытии и не зависит от времени входа второго партнёра.
- Каждый участник управляет собственным согласием на ежедневные вопросы. Выключение любым ставит новые вопросы и push на паузу для обоих. Старые вопросы можно закончить.
- Время и часовой пояс общие, меняются любым партнёром. Отдельный переключатель отключает только push для своего аккаунта.
- В профиле есть «Интимные вопросы · 18+». Нужны согласие и подтверждение совершеннолетия обоих. Это самоутверждение возраста, не проверка документов.
- При отзыве согласия ещё не раскрытые интимные вопросы отменяются без раскрытия ответов, а последующие вопросы будут обычными. В день отмены замены нет. Уже раскрытая история сохраняется.
- До второго ответа сервер возвращает только собственный ответ и общее число ответов. После второго оба ответа открываются и больше не редактируются. До раскрытия свой ответ можно изменить.
- Пропуск любым партнёром закрывает вопрос для пары, не раскрывая ранее отправленный ответ.
- История скрыта под раскрывающейся кнопкой. Загружается по 20 вопросов; «Ещё» запрашивает следующую порцию. Для этого вручную применить также `20261001050000_question_history_pages.sql` после основной миграции. Записи в базе не удаляются.
- Перед отправкой сервер повторно проверяет участие, паузу, согласие, время и личные настройки push. Интимный текст в push заменяется на «Для вас новый личный вопрос». Уже переданное системной службе уведомление отозвать нельзя.
- Для Android создаётся отдельный канал «Вопрос дня». Выключение его уведомлений не затрагивает желания.
- Если участник уже ответил, ежедневный push ему не отправляется. Отдельный push о раскрытии обоих ответов в эту версию не добавлен; экран обновляется при возвращении и каждые 20 секунд, пока открыт.
- Очередь создаёт не более одного задания на вопрос и получателя. При сбое после принятия push сервисом, но до подтверждения задания, редкий повтор возможен; точная минута доставки тоже не гарантируется.

## Банк вопросов

`daily_questions`: `body`, `topic`, `intimate`, `active`. Стартовый набор — 20 самостоятельно написанных вопросов (16 обычных, 4 интимных), без заимствования готовых упражнений. Это редакционный стартовый набор, не психологически валидированный инструмент.

Пополнение — через Supabase владельцем проекта. Не выдавать пользователям права на таблицу. Редактирование банка не изменяет уже назначенные вопросы: текст и интимность скопированы в `couple_daily_questions`.

Повторов нет: после исчерпания подходящих вопросов показывается сообщение, новые push прекращаются до пополнения банка. Для длительной эксплуатации банк нужно расширить до запуска на широкую аудиторию.

## Проверки

`node tests/personal-workspaces.cjs` выполняет все миграции в одноразовом локальном PostgreSQL и сценарии `daily-question-scenarios.cjs`: скрытие первого ответа, раскрытие после второго, запрет редактирования, изоляция третьего пользователя, общее время, отключение push, пауза, неповторяющиеся задания, возрастное подтверждение, согласие обоих, отзыв и пропуск.

Нужен ручной сквозной тест на двух аккаунтах/устройствах после миграции и развёртывания функции. Локальные тесты не подтверждают реальную доставку FCM/APNs и внешний Cron.
